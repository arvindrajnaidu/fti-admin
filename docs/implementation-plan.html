Atomic claim before send

// admin/pages/api/whatsapp/send-time-change-notification.js
await db.runTransaction(async (txn) => {
  const snap = await txn.get(orderRef);
  const data = snap.data();
  if (data?.recipientContact?.pendingSenderNotification !== true) return null;
  txn.update(orderRef, {
    'recipientContact.pendingSenderNotification': false,
    'recipientContact.senderNotifiedAt': admin.firestore.FieldValue.serverTimestamp(),
  });
  return data;
});
// only one transaction wins → only one email sends

Send email via Resend with the existing cancel-order.js shape. From: FoodtoIndia <orders@foodtoindia.com>, Reply-To: support@foodtoindia.com. Inline HTML template — short note showing old → new time + reassurance.

✓
No cron needed. Trigger is on dispatch-queue page load — admin scans the orders response for pendingSenderNotification: true and fires off a POST per order. Transaction guarantees dedupe across simultaneous tabs.

04Verification

End-to-end test plan, in order. Each phase ends with build-smoke before moving on.

  • Build smoke: npm run build in both repos. Must pass after every phase.
  • Template builder: small script admin/scripts/_test-whatsapp.js prints all 6 variants — eyeball before any UI work.
  • Admin button flow: click button on a test order. Verify: doc updated, wa.me URL opens correct phone+message, re-click reuses same token.
  • Confirmation page: paste URL in private window. Verify: loads without auth · form pre-fills · invalid token shows error · submit-same-time writes confirmed status · submit-different-time sets timeChanged & pendingSenderNotification.
  • Email auto-send: refresh admin dispatch queue. Verify Resend log shows the email; flag cleared in Firestore.
  • Ops address editor: verify both order doc AND recipients/{phoneE164} are written.
  • Profile accumulates: after recipient confirms, profile doc exists with addressSource:'recipient_confirmed'.
  • Status badges: dispatch queue shows correct pill for each state.
  • Phone test: open the wa.me link on an actual phone — does WhatsApp open with message pre-filled?
  • Mobile confirmation page: open /confirm/... on mobile — large taps, no horizontal scroll.
  • Off-hours: mock system clock to 2 AM IST, refresh confirmation page — ASAP gone, slot list starts tomorrow.

05Risks & ambiguities surfaced during build

None blocking. Flag each in implementation-notes.html as it's hit.

  • Address parsing of location.formattedAddress: Phase 1 punts on parsing area/city/state/pincode from the existing comma-string. Confirmation page leaves those fields empty for the recipient.
  • Legacy orders without recipientContact: UI must handle undefined cleanly — no badge, default button state.
  • Confirmation-page base URL: https://foodtoindia.com is hardcoded. Add NEXT_PUBLIC_CONFIRMATION_BASE_URL override for dev/stage testing.
